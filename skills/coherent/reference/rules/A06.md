# A06 — Duplicate representations

Investigation procedure only. Catalog metadata lives in
[taxonomy.md](../taxonomy.md). Detection: hybrid. Detector emits
`duplicate-rep:NameA+NameB` candidates from structural overlap. Record:
`decisions.json`. Shared write-back: [README.md](README.md).

## What to search for

Mechanical: interfaces, data-only classes, and type-literal aliases with ≥3
properties and ≥60% overlap (higher confidence when stems match).

Also inspect tables, documents, and DTOs the detector cannot see. The
detector’s own explanation is **not** a claim of semantic equivalence.

## Distinguish a real issue from an intentional difference

This repo’s standing example: `RuleCategory` and `CleanupPhase` share
`id` / `title` / `summary` by coincidence. They are intentionally different;
do not merge.

- Intentional: lifecycle or trust-boundary types with different invariants.
- Intentional: an extends/implements relationship (detector skips those).
- Real: the same information updates independently; mapping glue appears.
- Not A06: two functions that *do* the same work (A04); two named
  architectures (A05).

Never consolidate solely because shapes overlap.

## Evidence to collect

- Shared vs unique fields (already in detector details).
- Who writes each representation; which one persistence or API treats as
  authority.
- `semanticEquivalence` and `authoritativeConcept`.
- Mapping helpers that would die after a collapse (reconsider A08, B05,
  E04).

## Successful “do not merge”

`RuleCategory` vs `CleanupPhase`. Dismiss
`duplicate-rep:CleanupPhase+RuleCategory`. Write the authority into
`ARCHITECTURE.md` Authoritative representations.

## How to write the result

```text
coherent review dismiss <fingerprint> --reason "Share fields by coincidence. Taxonomy grouping is not a cleanup phase."
```

Set `semanticEquivalence` to the “do not merge” sentence and
`authoritativeConcept` to “keep both”. Confirm only when one representation
is truly redundant.
