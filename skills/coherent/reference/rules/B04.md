# B04 — Excessive indirection

Investigation procedure only. Catalog metadata lives in
[taxonomy.md](../taxonomy.md). Detection: hybrid. Detector emits
`forwarding:<file>:<name>` for single-call pass-throughs. Record:
`reviews.json`. Shared write-back: [README.md](README.md).

## What to search for

Mechanical: a function/method that accepts arguments, calls one downstream
with the same values, and adds no visible policy. Names or callees matching
authorize/validate/map/cache/log/retry/etc. are skipped.

Also inspect multi-hop service layers the detector will miss: A → B → C
where B only forwards.

## Distinguish a real issue from an intentional difference

- Intentional: the hop adds policy (authz, validation, mapping, transaction)
  even if the body is short.
- Intentional: a public export that must stay stable while the impl moves.
- Real: the hop hides the authoritative implementation; files must change
  together.
- Not B04: generic infrastructure (B02); helper sprawl (B05).

The detector marks some of these `confirmed`. Still review: independence of
policy is semantic.

## Evidence to collect

- Wrapper, callee, and callers.
- Policy that is actually present (or not).
- `authoritativeConcept`: the callee.
- `deletionOpportunity`: call the callee directly.

## Successful “do not merge”

A CLI command function that only parses flags then calls a run function is
a boundary, not a junk wrapper. Dismiss if argument mapping is the policy.

## How to write the result

Confirm or dismiss the fingerprint in `reviews.json`. If you find a
multi-hop chain the detector missed, append a hybrid finding with identity
`forwarding:<file>:<name>`.
