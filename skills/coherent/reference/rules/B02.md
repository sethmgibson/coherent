# B02 — Generic infrastructure

Investigation procedure only. Catalog metadata lives in
[taxonomy.md](../taxonomy.md). Detection: semantic. Record:
`decisions.json`. Shared write-back: [README.md](README.md).

## What to search for

A framework, pipeline, registry, plugin host, executor, or “platform” folder
built for a *family* of cases that has one or two real members.

- `register`, `plugins`, `pipeline`, `strategies`, `handlers.get(type)`
- Abstract workflow engines wrapping a single workflow
- Factory + interface + registry when only one production class is
  constructed
- Config-driven dispatch with one populated slot

In this product, detectors are ordinary functions called from `runAudit`. A
detector registry or plugin host here would be B02.

## Distinguish a real issue from an intentional difference

- Intentional: three or more production members with independent variation,
  or a hard external plugin boundary the product actually exposes.
- Intentional: language/framework registration you do not own (Nest
  providers, CLI command registration).
- Real: the next one-off is forced to become a plugin; understanding the
  framework costs more than the members.
- Not B02: one unused interface (B03); a forwarding wrapper (B04); a helper
  junk drawer (B05).

Prefer a small amount of duplicated obvious code over a premature generic
framework.

## Evidence to collect

- The infrastructure type and every registered member (production only).
- Call sites that must go through the framework vs those that could call the
  member directly.
- `authoritativeConcept`: the one or two real operations.
- `deletionOpportunity`: collapse to direct calls.
- `unlocks`: often D01 (framework packages) and A08.

## Successful “do not merge”

A CLI library that registers many real commands is not generic
infrastructure. Keep it. Record “no plugin host” in Forbidden dependency
directions if that is the standing rule.

## How to write the result

Append to the `findings` array in `.coherent/decisions.json`:

- `identity`: `generic-infra:<framework-or-registry>`
- `detectionMode`: `semantic`
- `status`: `confirmed` when member count is one or two and new work must
  register rather than call
