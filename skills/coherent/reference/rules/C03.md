# C03 — Boolean state explosion

Investigation procedure only. Catalog metadata lives in
[taxonomy.md](../taxonomy.md). Detection: hybrid. Detector emits
`boolean-params:*`, `boolean-branching:*`, and `bool-combo:*`. Record:
`reviews.json`. Shared write-back: [README.md](README.md). Look at C02 first:
flags often exist because a workflow was bent around one feature.

## What to search for

Mechanical: three or more boolean parameters; two booleans plus three
branches; the same flag set in multiple functions.

Also inspect status flags on objects (`isLegacy`, `isAdmin`, `isRetry`)
whose combinations are not a named state.

## Distinguish a real issue from an intentional difference

- Intentional: independent options that do not interact (logging on/off vs
  color on/off) with no illegal combinations.
- Real: impossible combinations can leak; each new flag doubles the state
  space.
- Two booleans alone are not enough (detector already requires more).

Prefer an explicit domain state over another flag.

## Evidence to collect

- Flag names, functions, and illegal combinations that compile today.
- The state model that should replace them.
- Tests that only cover the first product’s combination (C02).

## Successful “do not merge”

`dryRun` and `json` CLI flags are independent output options, not a hidden
state machine. Dismiss.

## How to write the result

Confirm in `reviews.json` when combinations are a missing state model.
Dismiss independent options.
