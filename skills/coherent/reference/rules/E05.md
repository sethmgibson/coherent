# E05 — Unnecessary sequential I/O

Investigation procedure only. Catalog metadata lives in
[taxonomy.md](../taxonomy.md). Detection: hybrid. Detector emits
`await-in-loop:*` and `seq-await:*`. Ordinary reviews report in chat; shared
write-back for explicit advanced cleanup: [README.md](README.md).

## What to search for

Mechanical: `await` inside a loop; sequential awaits whose independence is
inferred from identifier use only.

The detector suppresses control-flow-contained awaits and mechanically
recognizable filesystem ordering such as `mkdir` before `writeFile` and
`writeFile` before `chmod`. Other side-effect dependencies still require
semantic review.

Also inspect staged HTTP or disk reads with no data dependency.

## Distinguish a real issue from an intentional difference

The detector **intentionally** infers independence from identifier usage.
Side-effect-ordered operations (write then read, lock then mutate, rate
limits) look parallelizable and are often false positives.

- Intentional: the second await needs the first’s result or side effect.
- Real: independent I/O waits in sequence on a surviving hot path.
- Not E05: N+1 of the *same* query (E01).

Treat unreviewed E05 as a candidate. Do not auto-parallelize.
When concurrency is justified, bound it using input size, connection pools,
provider quotas and memory. `Promise.all` across a growing collection can
replace serial latency with excessive fan-out; use E06 to investigate missing
bounds. Preserve ordering, backpressure and per-item error/retry semantics.

## Evidence to collect

- Awaits, identifiers flowing between them, and side effects.
- Why order is or is not required.
- Input scale (a few config reads are not a finding).
- Proposed maximum in-flight work, resource/provider limits and behavior above
  the batch boundary, including retries and partial failures.

## Successful “do not merge”

`collectInventory` then `createAnalysisContext` must stay sequential. Dismiss
`seq-await` on that function if the second needs the first.

## How to write the result

Report only when independence and a safe concurrency bound are established.
In explicit advanced cleanup, confirm in `decisions.json` only with that
evidence. Dismiss or defer side-effect-ordered chains.
