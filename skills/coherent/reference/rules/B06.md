# B06 — Layer violations

Investigation procedure only. Catalog metadata lives in
[taxonomy.md](../taxonomy.md). Detection: hybrid. No detector ships yet.
Report in chat;
[shared boundaries](README.md) govern optional recording.

Do not repair boundaries around layers that B01–B05 should delete. First
choose the minimum surviving architecture.

## What to search for

Use existing architecture guidance and actual ownership/import directions to
establish intended boundaries, then find edges that go the other way: domain →
HTTP, catalog → CLI, persistence → UI. If intent cannot be established, explain
the uncertainty rather than inventing a forbidden direction.

In this repo, standing rules include: catalog must not import inventory,
detectors, or CLI; findings must not import inventory or CLI.

## Distinguish a real issue from an intentional difference

- Intentional: a direction the architecture never forbade.
- Intentional: a test file importing across layers.
- Real: a forbidden edge that new work will copy; the layering doc becomes
  fiction.
- Not B06: a fossil layer that should vanish (A01/B01) — delete it instead
  of “fixing” its imports.

## Evidence to collect

- The intended boundary and its evidence (documentation, ownership and imports).
- The violating import: files and symbols.
- Whether the source or the target should move.

## Successful “do not merge”

`src/catalog` and `src/plan` both deal with rules, but plan *reading* the
catalog is the allowed direction. Do not invert it.

## Advanced recording (explicit opt-in only)

Append `identity`: `layer-violation:<from>-><to>` as a hybrid/semantic
finding, or review a mechanical candidate. Confirm only against an established
boundary; inferred intent needs supporting source evidence.
