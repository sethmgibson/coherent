# D05 — Mock explosion

Investigation procedure only. Catalog metadata lives in
[taxonomy.md](../taxonomy.md). Detection: hybrid. No detector ships yet.
Record in `decisions.json`: review a current audit candidate when present;
otherwise add a semantic finding. Shared write-back: [README.md](README.md). Prerequisite
judgment: D04 (what the test asserts) before rewriting the mock graph.

## What to search for

Tests that construct a large mock graph to reach a unit, usually because the
unit is not separable or the test is not behavioral.

- `beforeEach` that creates many mocks (repos, clocks, loggers, queues,
  config).
- Deep `vi.mock` / `jest.mock` of internal modules to instantiate one
  function.
- Failures when a constructor gains a collaborator.
- Fixture objects that exist only to satisfy the mock graph.

Count production collaborators mocked vs behavioral inputs/outputs.

## Distinguish a real issue from an intentional difference

- Intentional: one mock at a true I/O or time boundary for a behavioral
  test.
- Intentional: a realistic fixture repository (this project prefers those
  over mocks).
- Real: mocks encode the current wiring. Deleting a hop looks like a mass
  test rewrite, so the hop survives.
- Not D05: interaction assertions on a small mock (D04). Not D05: unused
  test helpers (A08 in test trees is usually out of scope unless they block
  cleanup).

If the unit cannot be reached without a graph, the production design (B04,
C04) is often the finding. Do not grow a better mock pyramid.

## Evidence to collect

- Test file, setup size, mocked symbols.
- The production constructor or factory that forces the graph.
- `authoritativeConcept`: the observable behavior, or the collaborator that
  should remain a real fixture.
- `deletionOpportunity`: drop mocks after collapsing hops; or replace with
  a fixture.
- `unlocks`: B04/C04 cleanup that is currently “too expensive” because of
  tests.

## Successful “do not merge”

A fixture app under `tests/fixtures/` and a unit test that mocks `fs` for
one path are different tools. Keep both. Do not replace fixtures with mocks
or vice versa solely because both isolate I/O.

Review a mechanical finding if present. Otherwise append:

- `detectionMode`: `hybrid`
- `status`: `confirmed` when mock count is driven by wiring, not by one
