# B01 — Additive architecture

Investigation procedure only. Catalog metadata lives in
[taxonomy.md](../taxonomy.md). Detection: semantic. Record:
`decisions.json`. Shared write-back: [README.md](README.md).

Do this after A04–A06 have named surviving implementations. Do not spend
effort repairing boundaries around a layer that should be deleted.

## What to search for

Feature additions that *added a path* instead of changing the design that
should have absorbed the work.

- A new module, package, or “v2” folder beside a still-live one for the same
  job.
- Dual workflows: old checkout and new checkout, both extended.
- An extra layer introduced because changing the existing one looked risky.
- New handler/queue/job that repeats an existing entrypoint’s job.

Trace the new path and the old path from entrypoints. If both are in the
critical-workflow list, you are looking at B01 or a documented strangler.

## Distinguish a real issue from an intentional difference

- Intentional: a strangler or compatibility path with an actual consumer and
  a removal condition (A07). Additive only if both sides keep growing.
- Intentional: a new bounded context that does not claim the old job.
- Real: neither path is marked transitional; agents add to whichever they
  find first.
- Not B01: a fossil nobody extends (A01); a generic platform with one member
  (B02); a forwarding wrapper (B04).

Never preserve the extra path solely because many files already use it.

## Evidence to collect

- Old path and new path: files, symbols, callers.
- Which path the last features extended.
- Whether architecture documents one as transitional.
- `authoritativeConcept`: the design that should have absorbed the work.
- `deletionOpportunity` for the added path (or for the old one, if the new
  path is already authoritative).
- `unlocks`: A08, D01, and E-rules on the deleted path.

## Successful “do not merge”

A new provider adapter beside an existing one is required by an external
boundary, and the domain owner is unchanged. Record the provider boundary in
`ARCHITECTURE.md`. Do not emit a finding.

## How to write the result

Append to the `findings` array in `.coherent/decisions.json`:

- `identity`: `additive:<job>:<old-path>+<new-path>`
- `detectionMode`: `semantic`
- `status`: `confirmed` when both paths are still extended
