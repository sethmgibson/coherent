# E02 — Repeated computation

Investigation procedure only. Catalog metadata lives in
[taxonomy.md](../taxonomy.md). Detection: hybrid. No detector ships yet.
Ordinary reviews follow [data-access.md](../data-access.md) and report in chat.
Explicit advanced cleanup uses `decisions.json`; shared write-back:
[README.md](README.md). Fix ownership (A04/C01) first; then the leftover hot path.

## What to search for

Pure or expensive work recomputed in a loop or across layers: the same
map/filter/parse/hash, repeated schema validation, rebuilt indexes per
request.
Trace bulk imports, item-completion hooks and events that rebuild an entire
summary, index or cache after every item. Check whether one batch finalization
or an update of the affected scope would preserve required visibility.

## Distinguish a real issue from an intentional difference

- Intentional: recomputation because inputs changed or a write invalidated
  the result.
- Intentional: consumers require an authoritative intermediate result after
  each item. A batch optimization must preserve that contract.
- Real: a local variable or owner would be correct.
- Real: inputs change per item but no consumer needs intermediate rebuilds,
  and one recoverable batch finalization produces the same required result.
- Not E02: N+1 queries (E01); nested `.find()` (E06).

## Evidence to collect

- Expression, call sites, and why inputs are unchanged.
- The owner that should keep the result.
- Rebuild triggers/counts at representative batch sizes, affected scope and
  which intermediate states consumers observe.
- Finalization, transaction, crash/partial-failure and replay behavior. A
  deferred rebuild must still happen after partial completion when required.

## Successful “do not merge”

Two similar parses of different payloads. Keep both.

## How to write the result

Report repeated computation or rebuilds with scale, visibility and recovery
evidence. For explicit advanced cleanup, append a hybrid finding with
`identity`: `repeated-compute:<file>:<fn>`; no E02 detector ships. Confirm only
on a surviving hot path. Broad unnecessary refetches fit E03; avoid recording
the same rebuild/refresh chain twice.
