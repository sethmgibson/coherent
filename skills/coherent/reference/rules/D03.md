# D03 — Swallowed errors

Investigation procedure only. Catalog metadata lives in
[taxonomy.md](../taxonomy.md). Detection: hybrid. Detector emits
`catch:*` / empty-handler identities. Record: `reviews.json`. Shared
write-back: [README.md](README.md).

## What to search for

Mechanical: catch blocks that ignore, return empty, or log without changing
observable control flow.

Also inspect: `.catch(() => {})`, promise voids, mapping failures to
`undefined` at the center of a workflow.

## Distinguish a real issue from an intentional difference

- Intentional: a boundary that translates a known vendor error into a
  domain result the caller can see.
- Intentional: best-effort telemetry that must not fail the request, if
  the main path still reports its own errors.
- Real: the system continues in an undefined state; later cleanup cannot
  tell broken from intentional.
- Empty catch in tests is usually not D03.

## Evidence to collect

- Catch site, what is swallowed, and whether callers can observe it.
- The failure mode that should surface.
- Tests that pass because the error was eaten.

## Successful “do not merge”

A CLI that maps a user error to a non-zero exit (observable) vs a catch that
returns `[]`. Keep the CLI mapping; confirm the silent `[]`.

## How to write the result

Confirm in `reviews.json` when control flow is unchanged. Dismiss
translations that callers can observe.
