# C05 — Distributed workflow complexity

Investigation procedure only. Catalog metadata lives in
[taxonomy.md](../taxonomy.md). Detection: semantic. Record:
`semantic-findings.json`. Shared write-back: [README.md](README.md).

Look at this after B01 (which path is living) and C01 (where invariants
live). Do not invent orchestration for a workflow that should collapse.

## What to search for

One business workflow split across handlers, queues, crons, retries, and
sagas *without* an explicit owner or orchestration model.

- ARCHITECTURE.md Critical workflows / Async boundaries that list hops but
  no owner.
- A user action that continues in a queue consumer, then a cron, then
  another handler, with failure handled differently at each hop.
- Replay and idempotency invented per hop.
- New hops added because the existing path is hard to see.

Trace *one* business outcome end to end. Stop at the hops that outcome
actually uses.

## Distinguish a real issue from an intentional difference

- Intentional: an explicit state machine, saga, or documented orchestrator
  with one owner and known failure/replay rules.
- Intentional: a hard provider boundary (payments, email) called from one
  place.
- Real: the path is accidental; visibility is logs; agents add hops.
- Not C05: extra layers inside one process (B01/B04); a single handler with
  too many flags (C02/C03).

This repo’s CLI is synchronous. Absence of queues is not a finding.

## Evidence to collect

- The business outcome in one sentence.
- Ordered hops: file, symbol, trigger (HTTP, queue, cron).
- Who owns success, failure, and replay today (often: nobody).
- `authoritativeConcept`: the orchestration or the single remaining owner
  after collapse.
- `changeRisk`: replay, double-send, and visibility.
- Existing characterization tests, if any.

## Successful “do not merge”

Two queues that look similar: one is the order workflow, one is an unrelated
outbound email firehose. They stay distinct. Record both async boundaries.

## How to write the result

Append to `.coherent/semantic-findings.json`:

- `identity`: `distributed-wf:<workflow>`
- `detectionMode`: `semantic`
- `status`: `confirmed` when hops have no shared owner or failure model
