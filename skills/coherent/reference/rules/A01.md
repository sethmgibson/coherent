# A01 — Architecture fossilization

Investigation procedure only. Catalog metadata lives in
[taxonomy.md](../taxonomy.md). Detection: semantic. Record:
`semantic-findings.json`. Shared write-back: [README.md](README.md).

## What to search for

Start from `.coherent/ARCHITECTURE.md` (layers, forbidden directions, critical
workflows) and the inventory’s source directories. Then trace two or three
workflows from real entrypoints.

Look for:

- Folder or module names that describe a design the call graph no longer
  follows (`controllers/`, `use-cases/`, `domain/`, `hexagonal/`, leftover
  app packages).
- Documented layers that no inbound path from a bin, export, or handler uses.
- Features added in a new home because the documented home is empty or
  decorative.
- Comments or docs that speak in the past tense (“this used to be the API”,
  “legacy layer”).
- Config or README that still describes a multi-app or multi-layer split the
  tree no longer has.

Do not read the whole tree. Stay on the architecture file, entrypoints, and
the modules those workflows actually enter.

## Distinguish a real issue from an intentional difference

A fossil is a **named design that agents still extend** while the living
system works elsewhere.

- Intentional: a declared boundary that imports actually obey, or a
  transitional path with a named consumer and removal condition (see A07).
- Intentional: two similarly named modules that own different jobs (`analysis`
  vs `audit` in this repo). That is a “do not merge” result, not A01.
- Real: new work keeps landing in the unused layer, or every feature invents a
  parallel path because the documented home is unused.
- Not A01: unreachable files with no living design claim (A08); a *new* layer
  added beside a still-used one (B01).

Never keep a fossil solely because many files already sit in it.

## Evidence to collect

- Documented layers vs the folders and imports the traced workflows use.
- Specific import edges that ignore the declared direction.
- The last features’ landing sites vs the documented home.
- Exact files and symbols of the fossil and of the living path.
- `semanticEquivalence`: fossil name vs living design.
- `authoritativeConcept`: the living architecture, if you can name it.

## Successful “do not merge”

Two layer or module names look interchangeable, but they own different
jobs and the import graph treats them as distinct. Record that in
`ARCHITECTURE.md` (intentional architecture vs historical accident). Do not
emit a semantic finding just to close the question.

## How to write the result

If it is a real fossil, append a `Finding` to
`.coherent/semantic-findings.json`:

- `ruleId`: `A01`
- `identity`: `fossil:<layer-or-module>` (no line numbers)
- `detectionMode`: `semantic`
- `status`: `confirmed` when traced workflows never use the declared layer;
  `candidate` when only some paths diverge
- Fill evidence, locations, `authoritativeConcept`, `deletionOpportunity`,
  `unlocks`, `changeRisk`, `testSafetyEvidence`

Do not invent a mechanical candidate. A01 has no detector.
