# A08 — Dead code

Investigation procedure only. Catalog metadata lives in
[taxonomy.md](../taxonomy.md). Detection: deterministic. Detector emits
`unused:*`, `unused-candidate:*`, `test-only:*`, `unreachable:*`, `unreachable-false:*`.
Record: `decisions.json` when you override the machine status. Shared
write-back: [README.md](README.md).

## What to search for

Mechanical: no static symbol references in the analyzed files; statements after
return/throw/break/continue; `if (false)` branches. Python reports only
mechanically certain unreachable statements (`return`/`raise`/`break`/`continue`
and `if False`); it does not emit unused-symbol findings.

This is not a complete reachability graph from production entrypoints.
`test-only` candidates identify declarations whose static references outside
the declaration are all in test files. Evidence names the test locations;
self-recursion does not establish a production consumer. A barrel or another
production-file reference keeps the finding conservative: the detector does
not recursively prove that an entire call graph is test-only. Public APIs and
intentional test-support factories may correctly have only test consumers;
review that purpose before retiring code and tests.
Function declarations and var bindings are hoisted, and interfaces/type
aliases are erased: their placement after `return` is not deletion evidence.

The detector already stays conservative around DI, decorators, reflection,
CLI and framework registration, dynamic imports, jobs, public APIs, and
package exports — those become `unused-candidate`, not confirmed unused.
Python never treats missing references, `__all__`, decorators, public
exports, framework registration, reflection, or unknown imports as
deletion evidence.

For Nest, the detector recognizes imports of decorators from `@nestjs/common`,
including aliases and namespaces. It follows explicit module providers,
imports/exports/re-exports, `useClass`, `useExisting`, and factories that
directly return `new Service(...)` with an `inject` array. An exact constructor
binding into a readonly parameter property or field plus an actual port method
call establishes static use of that provider method. Registered HTTP handlers
and lifecycle methods also count as use. Mere type similarity or `Injectable`
alone does not. Competing tokens, missing module visibility, reassigned fields,
opaque factories/spreads, and test-only registrations do not establish proof.
This is bounded static registration analysis, not execution of Nest or a
complete bootstrap graph; unsupported dynamic patterns remain review work.
Base module imports stay separate from `DynamicModule` factory variants.
Literal factory returns can establish local bindings, but cross-module
resolution through configured `Module.register(...)` calls remains uncertain;
the detector does not substitute base-module bindings for those calls.

Re-run after A07, A04–A06, and B01–B05. Newly dead leftovers are the point.

## Distinguish a real issue from an intentional difference

- Intentional / keep: a proven runtime, framework, or external consumer.
  Dismiss with the specific caller or registration evidence.
- Real: confirmed unused with no dynamic or public reachability.
- Do not delete uncertain code merely because static references are absent.
- Exported helpers used only by tests may still be public API — check
  package exports.

Deterministic analysis may conclude only from mechanical evidence. Do not
upgrade a semantic question into a fake A08 confirmed.

## Evidence to collect

- Identity, file, symbol, and the detector’s details.
- Dynamic-use checks you re-verified (or why they do not apply).
- Tests that import the symbol.
- What else becomes unused after deletion.

## Successful “do not merge”

Not a merge rule. A successful negative names a proven consumer. If dynamic
or public reachability cannot be established or disproved, defer with that
uncertainty instead of dismissing the finding.

## How to write the result

Confirmed unused may already be plan-ready. For candidates you prove dead:
`coherent review confirm`. For proven live candidates: `dismiss` with the
caller/registration evidence. For uncertain candidates: `defer` with the
missing evidence. Do not add a semantic finding that
duplicates the mechanical one.
