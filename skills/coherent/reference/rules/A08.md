# A08 — Dead code

Investigation procedure only. Catalog metadata lives in
[taxonomy.md](../taxonomy.md). Detection: deterministic. Detector emits
`unused:*`, `unused-candidate:*`, `unreachable:*`, `unreachable-false:*`.
Record: `reviews.json` when you override the machine status. Shared
write-back: [README.md](README.md).

## What to search for

Mechanical: no static references from entrypoints; statements after
return/throw/break/continue; `if (false)` branches.

The detector already stays conservative around DI, decorators, reflection,
CLI and framework registration, dynamic imports, jobs, public APIs, and
package exports — those become `unused-candidate`, not confirmed unused.

Re-run after A07, A04–A06, and B01–B05. Newly dead leftovers are the point.

## Distinguish a real issue from an intentional difference

- Intentional / keep: anything the conservative checks flag as dynamic-use.
  Dismiss or leave as candidate.
- Real: confirmed unused with no dynamic or public reachability.
- Do not delete uncertain code merely because static references are absent.
- Exported helpers used only by tests may still be public API — check
  package exports.

Deterministic analysis may conclude only from mechanical evidence. Do not
upgrade a semantic question into a fake A08 confirmed.

## Evidence to collect

- Identity, file, symbol, and the detector’s details.
- Dynamic-use checks you re-verified (or why they do not apply).
- Tests that import the symbol.
- What else becomes unused after deletion.

## Successful “do not merge”

Not a merge rule. A successful negative is: “candidate only; dynamic or
public reachability not disproved.” Dismiss or leave unconfirmed.

## How to write the result

Confirmed unused may already be plan-ready. For candidates you prove dead:
`coherent review confirm`. For candidates you cannot prove: `dismiss` or
`defer` with the reachability reason. Do not add a semantic finding that
duplicates the mechanical one.
