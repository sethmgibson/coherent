# A03 — Implicit string protocols

Investigation procedure only. Catalog metadata lives in
[taxonomy.md](../taxonomy.md). Detection: hybrid. Detector emits
`string-protocol:<owner>:<value>` and `string-protocol-variants:<owner>:<normalized>` candidates.
Typed switch cases are filtered out. Findings are grouped by protocol owner
(`status`, `kind`, …), not by matching words alone. Record:
`decisions.json`. Shared write-back: [README.md](README.md).

## What to search for

Mechanical: repeated string literals used as `status` / `state` / `type` /
`kind` / `mode` / `event` / `action` / `phase` / `reason` / `discriminator`,
including spelling or case variants.

Also inspect by hand: magic prefixes (`evt_`, `job:`), concatenated tokens,
and string unions copied in two modules. Do not treat every repeated string
as a protocol (paths and prose are already filtered).

## Distinguish a real issue from an intentional difference

- Intentional: a documented string contract at an external boundary (HTTP
  webhook, queue payload) with one parser.
- Intentional: log messages or user-facing copy.
- Real: producers and consumers can drift; a refactor cannot find every
  participant.
- Not an automatic enum recommendation. Confirm the values are a *behavior*
  contract, not labels.

`FindingStatus` (`confirmed` | `candidate`) in this repo is a typed
protocol. Do not invent a parallel string protocol beside it.

## Evidence to collect

- Literal values, files, and the property they discriminate.
- Variant spellings of the same token.
- Whether architecture already names the protocol.
- `authoritativeConcept`: the type, enum, or schema that should own it.

## Successful “do not merge”

`"confirmed"` as a finding status and `"confirmed"` as a payment state are
different protocols. Keep both. Dismiss the pair if the detector grouped
them.

## How to write the result

`coherent review confirm|dismiss|defer` the fingerprint from the current audit output.
If you find a protocol the detector missed, append a hybrid `Finding` to
`decisions.json` with identity `string-protocol:<owner>:<value>`.
