# C04 — Context object explosion

Investigation procedure only. Catalog metadata lives in
[taxonomy.md](../taxonomy.md). Detection: hybrid. Detector emits
`context-object:<file>:<Name>` for large objects passed broadly. Record:
`decisions.json`. Shared write-back: [README.md](README.md).

## What to search for

Mechanical: bags with many properties and multiple consumers. Also:
`Options`, `Context`, `Bag`, `Meta` threaded through the stack; every new
field becomes ambient state.

Ask which fields each hop actually reads.

## Distinguish a real issue from an intentional difference

- Intentional: a request-scoped context with a small, documented contract
  (auth identity, request id).
- Intentional: a config object owned at the process boundary.
- Real: callers cannot tell what is required; fields exist because no one
  owns the real inputs (often after B04 hops).
- Not C04: a domain type with many required fields and one owner (maybe
  A06 if it is a duplicate representation).

## Evidence to collect

- Bag type, properties, and which consumers read which fields.
- Required vs optional vs unused.
- `authoritativeConcept`: explicit arguments or a smaller owned type.

## Successful “do not merge”

`AnalysisContext` in this repo is a scan-scoped owner, not a dumping ground.
Dismiss if consumers use the same known surface.

## How to write the result

Confirm in `decisions.json` when the bag hides missing ownership. Dismiss a
narrow, documented context.
