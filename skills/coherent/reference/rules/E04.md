# E04 — Serialization overhead

Investigation procedure only. Catalog metadata lives in
[taxonomy.md](../taxonomy.md). Detection: hybrid. No detector ships yet.
Record: `semantic-findings.json` until a candidate exists, then
`reviews.json`. Shared write-back: [README.md](README.md). Collapse
representations (A06) first; leftover mappings often disappear.

## What to search for

Encode / copy / map through several representations on one path without a
boundary that requires it: domain → DTO → JSON → DTO → domain; structured
clone plus `JSON.parse(JSON.stringify)`.

## Distinguish a real issue from an intentional difference

- Intentional: a mapping at a real process, persistence, or provider
  boundary.
- Real: each extra mapping is another A06 hiding place and a cost that
  vanishes if one representation is canonical.
- Not E04: a single boundary mapper after A06 chose an authority.

## Evidence to collect

- Ordered representations on one path.
- Which hop is required by a boundary.
- Mapping helpers that B05/A08 would delete after canonicalization.

## Successful “do not merge”

Inventory JSON vs `ARCHITECTURE.md` quoting inventory facts: two
representations with different jobs (machine snapshot vs durable prose).
Keep both; do not add a third.

## How to write the result

Append `identity`: `serde-overhead:<path>` or review a mechanical finding.
Confirm only after A06 is decided.
