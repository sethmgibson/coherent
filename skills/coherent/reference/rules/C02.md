# C02 — Feature overfitting

Investigation procedure only. Catalog metadata lives in
[taxonomy.md](../taxonomy.md). Detection: semantic. Record:
`decisions.json`. Shared write-back: [README.md](README.md).

## What to search for

A *general* workflow, type, or pipeline that has been bent around one
feature’s shape.

- Optional fields that are required for feature X and meaningless otherwise.
- Switches on feature name, customer name, ticket id, or “isEnterprise”.
- Step lists that only make sense for the first product, while the type
  claims to be generic (`OrderPipeline`, `WorkflowEngine`, `BaseHandler`).
- Neighboring cases that already forked the workflow or added a flag (C03
  often follows).

Read the type or workflow and ask what a second product would have to
break.

## Distinguish a real issue from an intentional difference

- Intentional: a dedicated feature module that does not claim generality.
- Intentional: a strategy with several real members (not B02) that share a
  small interface.
- Real: the next feature either forks the workflow or adds another flag.
- Not C02: a catch-all context bag (C04); a missing upstream invariant (C01);
  an extra path added beside the general one (B01).

Do not “generalize” by adding more optionals. Prefer an explicit domain
operation for the special case, or admit the workflow is feature-local.

## Evidence to collect

- The general type/workflow and the feature it actually fits.
- Fields or steps that only that feature uses.
- The awkward neighboring case (or the fork that already exists).
- `authoritativeConcept`: either a feature-local module or a truly shared
  operation with explicit variation.
- `unlocks`: C03/C04 often shrink if this is fixed first.

## Successful “do not merge”

A `Checkout` workflow and a `Refund` workflow share payment types but are
not the same pipeline. Keep them. Record both under Critical workflows.

## How to write the result

Append to the `findings` array in `.coherent/decisions.json`:

- `identity`: `overfit:<type-or-workflow>`
- `detectionMode`: `semantic`
- `status`: `confirmed` when a second case already forked or cannot enter
  the workflow without a new flag
