# A02 — Terminology drift

Investigation procedure only. Catalog metadata lives in
[taxonomy.md](../taxonomy.md). Detection: semantic. Record:
`semantic-findings.json`. Shared write-back: [README.md](README.md).

## What to search for

Read the Canonical terminology and Domain concepts sections of
`.coherent/ARCHITECTURE.md`. Then search identifiers, table or collection
names, API fields, and docs for the same idea under different words — or one
word used for two ideas.

Typical pairs:

- Payment / Charge / Invoice / Order / Transaction
- User / Account / Profile / Customer / Member
- Store / Repository / Gateway / Client for the same resource
- `status` as workflow state vs HTTP status vs job result
- Stem collisions: `UserDto`, `UserModel`, `UserRecord`, `UserEntity`

Phase 2 work is a map, not a mass rename. Renames wait until they support a
real consolidation (A04–A06).

## Distinguish a real issue from an intentional difference

- Intentional: lifecycle or trust-boundary names with different invariants
  (`DraftPayment` vs `SettledPayment`; public DTO vs internal model) when
  `ARCHITECTURE.md` already says they stay distinct.
- Intentional: an external vendor name mapped once at the provider boundary.
- Real: every change translates; later work invents another synonym instead of
  using the canonical term.
- Not A02: two types that share fields but already have a declared authority
  (A06). Not A02: two implementations of the same named behavior (A04).

Never merge names solely because they share a stem.

## Evidence to collect

- Competing names grouped by concept, with files and symbols.
- Where each name appears: persistence, API, domain, docs.
- Proposed canonical term, preferably from architecture context.
- `semanticEquivalence` for each pair you considered.
- Whether a rename is needed now, or only a glossary entry.

## Successful “do not merge”

`Rule` vs `CleanupPhase` vs `Finding` (this repo): different concepts, keep
the three names. Write the glossary into `ARCHITECTURE.md` Canonical
terminology. Do not add a semantic finding just to say that.

## How to write the result

If drift is real, append a `Finding` to `.coherent/semantic-findings.json`:

- `ruleId`: `A02`
- `identity`: `term-drift:<concept>`
- `authoritativeConcept`: the chosen term
- `semanticEquivalence`: how the names compare
- `deletionOpportunity`: usually “none yet — record the term; rename when it
  supports consolidation”
- `status`: `confirmed` when the architecture file and code disagree on the
  same concept; `candidate` when you only have a cluster of synonyms

Do not perform the rename in the audit.
